# Source Authority

This document controls how project sources may be used. Authority is claim-specific: a source may control one topic while providing context only on another.

## Current controlling sources

Use these sources as the controlling project record within their respective scopes:

- Explicit current owner decisions
- `sources/current/South_Andrews_Corrected_Assumptions.md`
- `sources/current/South Andrews 6v8 Story Model.xlsx`
- `sources/current/South_Andrews_8M_Construction_Feasibility.xlsx`

An explicit current owner decision controls only when its content, date, decision-maker, and scope are documented. Model outputs do not convert model inputs into verified facts.

## Current but subordinate context

- `sources/current/Andrews ODP with Dashboard.docx`

Use this document for institutional program logic and project requirements. It may not override corrected assumptions, newer models, or explicit current owner decisions.

## Third-party references

- `Andrew's Appraisal.pdf` — repository path: `sources/reference/Andrew’s Appraisal.pdf`
- `Appraisal Valuation.xlsx` — repository path: `sources/reference/Appraisal Valuation .xlsx`
- `sources/reference/NativeRealty_905 S Andrews - Development Feasibility & Massing Study.pdf`

Use each third-party reference only within its proper professional, geographic, temporal, and methodological scope. Identify the author, date, assumptions, and limitations before relying on it. Third-party conclusions do not become owner decisions or verified current conditions merely by appearing in these files.

The first two repository filenames differ typographically from their expected display names. Preserve the repository filenames until the owner explicitly authorizes renaming.

## Legacy narrative

- `sources/legacy/Institutional Development Prospectus Vol0.docx`

Use this document only for structure, tone, and still-valid evidence that is reverified against an authoritative source. Its naming, program, figures, and conclusions are not controlling.

## Conflict-resolution process

For every material conflict:

1. Identify both claims faithfully.
2. Identify each source and its date.
3. Determine each source's authority and scope.
4. Adopt a value only when the hierarchy, scope, and evidence justify it.
5. Otherwise mark the conflict unresolved and escalate it for owner review.
6. Never average conflicting values.
7. Never choose the more attractive value merely because it improves the project.

Preserve the noncontrolling claim as a superseded assumption, rejected scenario, or unresolved item as applicable. Then check every downstream use for consistency.
