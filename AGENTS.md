# Shared Agent Operating Contract

## Repository purpose

This canonical repository supports the evidence-based planning, analysis, and eventual external communication of the **South Andrews Healthcare and Mobility Hub**. All coding and research agents must preserve source integrity, distinguish evidence from judgment, and present the project's current status accurately.

## Required reading order

Before substantive work:

1. Read this `AGENTS.md`.
2. Read `CLAUDE.md` when operating as Claude.
3. Read `docs/governance/SOURCE_AUTHORITY.md`.
4. Read `docs/governance/PROJECT_GLOSSARY.md`.
5. Read `docs/governance/CLAIMS_AND_EVIDENCE_POLICY.md`.
6. Read `docs/governance/WORKFLOW.md`.
7. Read the relevant `skills/*/SKILL.md` before performing source reconciliation, financial-model audit, or prospectus work.
8. Inventory applicable sources before synthesis; do not infer document content from filenames.

## Source-precedence hierarchy

Resolve claims using this order, subject to each source's proper scope:

1. Explicit current owner decisions
2. `South_Andrews_Corrected_Assumptions.md`
3. `South Andrews 6v8 Story Model.xlsx`
4. `South_Andrews_8M_Construction_Feasibility.xlsx`
5. Current owner-approved development program
6. Verified primary sources
7. Appraisal and third-party studies
8. Prior prospectuses and legacy concepts

Higher precedence does not make a source authoritative outside its scope. Follow `docs/governance/SOURCE_AUTHORITY.md` when claims conflict.

## Operative governance succession

`AGENTS.md` and the current `docs/governance/` set are the operative repository governance system. An authenticated prior Project Constitution or Decision Log, if recovered, enters the repository as historical evidence and does not automatically supersede this system. It must first be reconciled and, where material, submitted for owner decision. The missing prior documents remain tracked dependencies; they must not be silently recreated or cited as presently operative.

## Evidence classifications

Classify every material claim as exactly one of:

- **verified fact** — independently supported by an authoritative primary source
- **source-derived but not independently verified** — faithfully extracted from a source but not independently confirmed
- **current working assumption** — an active planning input awaiting validation or approval
- **model output** — calculated by an identified model from stated inputs
- **recommendation** — professional judgment or a proposed course of action
- **open question** — material information not yet resolved
- **superseded assumption** — formerly used but displaced by a more authoritative current source
- **rejected scenario** — explicitly considered and not adopted

Do not blur, combine, or silently promote these classifications.

Structured records may also carry a separate statement type such as `owner_decision`, `adopted_strategy`, `scenario`, `historical_claim`, `unresolved`, or `missing_source_dependency`. Those types do not replace the evidence classification and do not promote a strategy, assumption, or model output into a verified fact.

## Status discipline

- State what is proposed, modeled, verified, approved, committed, and unresolved.
- Treat all partner organizations as prospective unless a documented commitment establishes otherwise.
- Do not imply site ownership, entitlement, design approval, City support, utility capacity, partner commitment, demand, cost certainty, or returns.
- Label planning-level estimates and illustrative renderings wherever they appear.
- Stop and report a material unresolved conflict rather than concealing it in polished prose.

## Change discipline

- Make the smallest change necessary for the assigned phase.
- Preserve provenance, source filenames, and superseded assumptions.
- Do not move, rename, delete, or rewrite sources without explicit owner instruction.
- Record derived work separately from source material.
- Do not begin implementation during planning or source-organization work.
- Verify material claims against original sources during implementation.
- Keep downstream narratives, calculations, tables, captions, and disclosures consistent with adopted values.

## Original workbook protection

Never edit an original source workbook. Inspect workbooks read-only and place calculations, normalized data, annotations, and derived summaries in separate files with clear provenance.

## Version-control authority

Do not commit or push without explicit instruction. Do not infer authorization to commit or push from authorization to create, edit, validate, or stage files.
